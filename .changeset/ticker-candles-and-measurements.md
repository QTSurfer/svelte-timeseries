Candles from ticks and tickers, cleaner price scales, and a corrected README.

- **Ticker feeds no longer draw their 24-hour statistics as candles.** A ticker row holds a last price plus the open, high and low of a rolling window, so reading those columns as bar prices drew every candle across the whole day's range. A Parquet or Lastra table with OHLC-looking columns and `bid` / `ask` columns is now recognized as a ticker feed (from its schema alone) and its last price is aggregated into candles of `resolution` in DuckDB (first, highest, lowest and last price per bucket). Without a `resolution` the price is drawn as a line and the console explains how to get candles. An explicit `candlestick: { open, high, low, close }` mapping is still honored, so a bar file that carries `bid` and `ask` columns can opt back in.
  Behaviour changes to know about: `DuckDB.resolveOHLC` now returns `undefined` for such a table (the new `resolveTickCandles` describes it), and a bar file that happens to carry both `bid` and `ask` columns is drawn as a line (or, with `resolution`, from its close column) until you give it an explicit `candlestick` mapping.
- **`candlestick: { price: 'column' }`** builds candles from the ticks of any numeric column at `resolution`, for tick data, for tickers whose last price is not detected, and for tables that only have a price column. Viewport reloads and columns toggled on top of the candles are aggregated the same way. `DuckDB` gains `resolveTickCandles`, and `getOHLC` / `getWindowedOHLC` take an optional trailing `price` argument.
- **Columns added on top of resampled candles are now resampled too** instead of being loaded as raw rows that did not line up with the candles. This also applies to bar data that sets `resolution`.
- **New `aggregateCandles(ticks, interval)`**, exported by both packages: a pure function that aggregates a price line (`times`, `values`, optional per-tick `volumes`) into OHLC bars of `'1s'`, `'5s'`, `'1m'`, `'1d'` or any number of milliseconds. Buckets are aligned to the Unix epoch (UTC), empty buckets are skipped, unsorted input is sorted and ticks that are not finite numbers are skipped.
- **`candles` also accepts a price line to aggregate**: `candles={{ times, values, interval: '1m' }}` on `TimeSeriesChart` and `SvelteTimeSeries`. New types `CandleInterval`, `CandlesSource`, `PriceTicks`, `TickCandlesInput` and `AggregatedCandles`.
- **Price scales ignore floating-point noise.** A value such as `0.1 + 0.2` no longer widens the scale to 16 decimals or shows up as `0.30000000000000004` in labels and tooltips: values with 15 or more significant digits are shown with the fewest decimals at which they still equal themselves within a relative 1e-13. Prices with up to 14 significant digits, such as eight-decimal crypto prices and micro prices, keep every decimal; a genuine 15-digit value loses its last digit. Over the price, bid, ask, open, high and low columns of the sample files nothing changes; only indicator and volume columns that carried noise show fewer decimals. Clean series cost the same as before and noisy ones about 12 ms more per 100k values.
- `addMarkerPoint` accepts `shape` as an alias of `icon` on both backends.
- README fixes, checked by running every example: the getting-started example needs an absolute file URL and a markers table that exists, `setDataset` takes the time column in its names list, the package README no longer imports builders that the package does not export, `resolution` is documented as resampling bars (or aggregating ticks with `candlestick: { price }`), Lightweight Charts is no longer described as "line only", and the development commands are the ones that exist. The package README now mirrors the main one. New Performance section with measurements for 10k to 250k points and recommended limits, a ticks-to-candles scenario in the `/injected` demos, and `scripts/measure-performance.mjs` to reproduce the numbers.
